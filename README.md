# PowerShell RPA Studio

Windows PowerShell 5.1で動く、シナリオ編集・保存・実行用GUIです。追加インストールは不要です。

## 起動

`Start-Rpa.vbs`をダブルクリックします。コンソール（黒い画面）を表示せず起動します。従来の`Start-Rpa.cmd`も同じランチャーを呼び出しますが、cmd自身の画面が一瞬出ることがあるため、通常はvbsを使用してください。組織の実行ポリシーやWindows Script Hostの制限により起動できない場合は管理者に確認してください。

## 使い方

1. 「操作追加」で選択行の上、「操作追加（下）」で選択行の下に追加し、操作・値・座標・操作後の待機時間を編集します。複数行選択時は「操作追加」が一番上の選択行の直前、「操作追加（下）」が一番下の選択行の直後に追加します。未選択時はどちらも末尾に追加し、新しい行を自動選択します。
2. マウス操作は対象の画面を表示して「座標取得」を押し、3秒以内に対象へマウスを移動します。選択行のX/Yへ反映されます。
3. 「名前を付けて保存」でJSONとして保存し、「開く」で再利用できます。Ctrl＋Sは現在のファイルに上書き保存します。未保存の場合は保存先を選択します。
4. 「実行」を押し、3秒以内に操作対象のウィンドウを前面へ表示します。
5. 停止する場合はEscを長押しするか、GUIの「停止」を押します。エラー発生時も後続操作を停止します。

画面下部には現在のマウス位置（X・Y）を約0.1秒間隔で表示します。

### 部分実行

左端の行見出しをクリックして行を選び、「選択行を実行」を押します。Ctrlを押しながらクリックすると離れた複数行、Shiftを押しながらクリックすると連続した範囲を選択できます。選択行はシナリオの上から順に実行され、ログに元の行番号を表示します。「全体実行」は選択状態にかかわらず全行を実行します。部分実行の前に、対象画面を必要な状態まで準備してください。

「削除」は選択したすべての行を削除します。座標取得と上下の並べ替えは1行を選択して使用してください。

|操作|値|
|---|---|
|待機|ミリ秒（1000 = 1秒）|
|マウス移動・各クリック|X/Yに画面座標を入力。値は不要|
|文字入力|入力したい文字。日本語対応。クリップボード経由で貼り付け|
|ID入力・パスワード入力|「入力情報設定」で登録した暗号化情報を使用。値列へ直接記入しない|
|キー送信|SendKeys書式。`{ENTER}`、`{TAB}`、`^a`（Ctrl+A）、`^l`（Ctrl+L）、`%{F4}`（Alt+F4）など|
|URLを開く|http/httpsのURL。既定のブラウザで開く|
|アプリ起動|実行ファイルのパスまたは`notepad.exe`など。引数指定は非対応|

## 行コピー・キー回数・ウィンドウ指定・RPA終了

「行コピー」は、選択行を一番下の選択行の直後へ複製します。Ctrl／Shiftで選んだ複数行も上からの順番でコピーし、コピーした行を選択します。暗号化したID・パスワード、日付設定、対象要素、キー回数も引き継ぎます。前回の実行状態はコピーしません。システムのクリップボードは使いません。

「キー送信」は「キー回数」列で繰り返し回数を指定します（1～10000回、空欄や従来のシナリオは1回）。例：値を `{TAB}`、キー回数を `3` にするとTabを3回送ります。半角スペースキーは `{SPACE}` と指定できます（RPA独自の表記で、実行時にスペース文字へ変換します）。値に複数キーを書いた場合は、その一連のキーを指定回数繰り返します。繰り返しの間は50ms待機し、実行停止やEscでも中断できます。「操作後の待機」は全回数の送信が終わってから適用します。他の操作ではキー回数を使用しません。

対象アプリを前面に出したい場合は、行を選んで「ウィンドウ指定」から対象を選択します。操作は「ウィンドウをアクティブ化」になります。値にタイトルを直接入力しても指定できます。指定ボタンを使った場合はアプリ名とウィンドウクラスも保存し、タイトルが変わっていても同じ条件のウィンドウが1つなら検索できます。複数候補では停止します。最小化されている場合は復元し、前面になったことを確認します。対象を起動する操作ではないので、先にアプリを開いてください。Windowsの制限や権限の違いで前面化できない場合は10秒で停止します。参考：[SetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)。

シナリオの最後に「RPA終了」を追加すると、その行の待機後にRPA画面を閉じます。後ろに行があっても実行しません。実行用VBSでも同じ動作です。シナリオの自動保存は行わないため、作成・編集した内容は先に保存してください。Excel・ブラウザなど他のアプリはこの操作では閉じません。「RPA終了」の操作後待機中に停止・エラーになった場合は、RPA画面を閉じずに残します。

これらの設定はJSON・実行用VBSにも保存されます。`Test-WorkflowFeatures.ps1` は複数行コピー・暗号化情報の引継ぎ・キー回数・停止・ウィンドウ復元／前面化・終了操作をテストします。

## 画像認識でクリックする

1. 対象アプリやリモートデスクトップの画面を表示し、登録先の行を選択します。
2. 「画像取得」を押します。RPA Studioが最小化され、画面が一時的に静止した選択画面になります。
3. 対象のボタンなどをドラッグで囲んでください。Escで中止できます。文字・マークを含む小さな範囲を選んでください（幅8～600px、高さ8～400px）。
4. 見本画像を保存し、通常は操作が「画像クリック」になります。クリックは見本画像全体の中心なので、中心がボタン内になるように切り取ります。
5. 実行前に対象画面を手前へ表示してください。「ウィンドウをアクティブ化」を前の行に入れることもできます。

### 見本画像の右・上・下などをクリックする

画像操作の行を選択し、上部の「画像設定」を押してください。見本のプレビュー、横・縦のずらし量、色の許容差を設定できます。基準は画像の中心で、単位は実画面のピクセル（px）です。

|クリック位置|横|縦|
|---|---:|---:|
|画像の中心|0|0|
|右へ50px|50|0|
|左へ30px|-30|0|
|上へ20px|0|-20|
|下へ40px|0|40|
|右へ50px、下へ20px|50|20|

例えば「項目名」の画像を見つけ、その右にある入力欄をクリックする用途に使えます。「画像クリック」「画像ダブルクリック」に適用され、「画像待機」ではずらし量を使用しません。ずらした結果が画面外になる場合はクリックせず停止します。設定はコピー・JSON保存・実行用VBSへの書き出しでも引き継がれます。以前の見本画像は横0・縦0として動作します。「画像取得」で見本を取り直すと、ずらし量は0に戻るため必要に応じて設定し直してください。

|操作|動作|
|---|---|
|画像クリック|見本画像を画面から探し、中心を左クリック|
|画像ダブルクリック|中心をダブルクリック|
|画像待機|見本画像の出現を待つ。クリックはしない|

検索範囲は表示されている全モニターです。見つからない場合は最大10秒待ちます。複数候補があればクリックせずエラーにします。検索中の停止ボタン・Escにも対応します。見本画像はPNGとしてJSON・実行用VBS内に保存されるため、別の画像ファイルを配布する必要はありません。選択範囲の画像は暗号化しないため、機密情報やパスワードが写らない範囲を選んでください。

同じ大きさの画像を色の差を許容して探す方式です。AIによる意味の理解、OCR、自動拡大縮小は行いません。取得時と実行時で表示倍率・リモート画面の解像度・テーマ・ボタンの状態などを揃えてください。初期の色許容差は20（RGB各成分の差、設定値は0～100）です。見つからない場合は、まず同じ表示状態で見本を取得し直してください。

リモートデスクトップを手元から操作する場合は、接続先の画面を表示したままにしてください。最小化・切断・ロック・画面が他のウィンドウで隠れた状態では対象を認識できません。文字やマークのない単色に近い画像は登録時に拒否します。

`Test-ImageAutomation.ps1` で画像の一致位置・複数候補・ドラッグ範囲の取得・実画面でのクリック・実行用VBSへの画像埋め込みを検証できます。画像操作を含むVBSを作り直す場合は、最新版から保存してください。

## ブラウザ操作例

すぐに入力を試す場合は `examples/space-input.json` を「開く」で読み込んで全体実行してください。サンプル専用のテキストエリアを開き、半角スペースキー5回、改行、Tab3回、実行日の入力を行います。起動時にブラウザや外部サイトを使う必要はありません。詳しくは `examples/スペース入力サンプルの使い方.md` を参照してください。

1. 「URLを開く」：`https://example.com`、操作後の待機を3000msに設定。
2. 「キー送信」：`^l`でアドレスバーへ移動。
3. 「文字入力」：移動先のURLを入力。
4. 「キー送信」：`{ENTER}`。

Webフォームはクリックで入力欄を選択し、「文字入力」と`{TAB}`、`{ENTER}`などで操作できます。EdgeやChromeをWindowsの既定のブラウザに設定してください。

## ボタン・入力欄を指定する（要素操作）

1. 操作を追加し、その行を1行選択します。
2. 「要素取得(3秒後)」を押し、3秒以内に対象アプリやWebページのボタン・入力欄へマウスを合わせます。
3. 「対象要素」列に識別情報が入り、対応している操作が自動設定されます。
4. 「要素入力」では「値」に入力する文字を指定します。既存の内容は置き換えます。「要素クリック」はボタンの実行、「要素フォーカス」は対象へのフォーカス移動です。
5. 通常と同様に保存・実行・部分実行できます。既存の座標シナリオも読み込めます。

取得時にのみマウスを使用し、実行時は同じプロセス名のアプリの全ウィンドウから、要素の種類・AutomationId・要素名で検索します。ウィンドウ名は取得時の参考情報として保存しますが、検索条件に使用しません。タイトルが変わっても対象要素を検索でき、既存のシナリオにも適用されます。見つからない場合は最大10秒待機し、複数一致した場合は候補件数を表示して停止します。同じ要素があるウィンドウを複数開いている場合は、対象以外を閉じてください。ページ切替で対象要素そのものの識別情報が変わった場合は再取得してください。「対象要素」列はJSON形式で直接編集できますが、通常は取得ボタンを使ってください。

この「要素取得」はWindows UI Automationを利用します。WebページもブラウザがUI Automationへ公開している要素を対象にできます。WebのHTML要素を取得する場合は、次の「ウェブ要素取得」を使用してください。独自描画のボタンやcanvasなどには座標方式を併用してください。

## WebのID・class・タグを取得して操作する

1. 上部の「Webブラウザ起動」を押します。RPA専用プロファイルのEdgeが開きます。通常のEdgeとはログイン情報が別なので、必要なサイトへログインしてください。URL行を選んでから押すと、そのURLを開きます。
2. 専用Edgeで対象ページを表示し、RPA Studioで操作を追加して登録先の行を選びます。
3. 「ウェブ要素取得」を押します。複数のページがある場合は対象を選びます。ページ上に案内が出たら、対象のボタン・入力欄などをクリックしてください。取得用クリックでは通常のクリック動作を抑止します。
4. 「対象要素」列にID・class一覧・タグ名・CSSセレクター・ページURLがJSON形式で保存されます。IDが一意ならIDを優先し、name属性・class・タグの階層などから一意なセレクターを作ります。
5. 通常は取得した行が「ウェブ要素クリック」に設定されます。「ウェブ要素クリック」ボタンでも選択行をその操作に設定できます。このボタン自体ではページをクリックせず、「選択行を実行」「全体実行」で実行します。

シナリオから対象ページを開く場合は、操作に **「Web用URLを開く」**、値にURLを設定してください。実行対象の行にWeb専用操作やWeb対象のID・パスワード入力が含まれる場合は、従来の「URLを開く」も自動的に専用Edgeで開きます。Web操作のない実行では「URLを開く」は従来通り既定のブラウザを開きます。Web用URL操作は常に専用Edgeを使用します。専用Edge内に同じURLのタブが1つある場合はそのタブを再利用します。取得後に通常のEdgeへ戻して実行しないでください。部分実行では、選択した行の内容でブラウザを判定します。

入力欄は「ウェブ要素入力」にして値を指定すると内容を置き換えます。ID・パスワードを入力する場合は、先に「ID入力」「パスワード入力」を選び、「入力情報設定」で登録してから「ウェブ要素取得」を行ってください。専用操作では暗号化情報を復号し、DOM経由で対象欄へ入力します。「ウェブ要素入力」の値は平文保存です。

実行時は、専用Edge内のURL（ホストとパス。クエリとハッシュは除外）とセレクターで探します。ウィンドウ名には依存しません。同じURLのタブや一致要素が複数あれば停止し、見つからない・非表示・無効・他の要素に隠れた状態では最大10秒待機して停止します。取得は最大60秒待ち、Escや上部の「実行停止」で中止できます。

対象は通常のHTML要素です。iframe内部・Shadow DOM内部・canvas・ブラウザのツールバーや設定画面は、この取得方式の対象外です。サイト改修や動的なID・class変更で再取得が必要な場合があります。取得中はページ移動を避けてください。ページ独自の先行イベント処理までは抑止できない場合があります。

Edge DevTools Protocolを使うため、追加ドライバーやNode.jsのインストールは不要です。専用プロファイルは `%LOCALAPPDATA%\PowerShellRpaStudio\WebProfile` に保存され、接続先はローカルPCの専用Edgeだけです。通常のEdgeへの接続や保存済みパスワードの読み取りは行いません。組織のブラウザポリシーがリモートデバッグを禁止している場合は利用できません。専用Edgeはアプリ終了後も残るため、使い終わったら閉じてください。

ローカルのテストページとEdgeで、ID/class/タグ取得、クリック、文字入力、暗号化パスワード入力、重複候補の停止、実行ファイルへの書き出しを検証しています。外部の各サイトでの動作は個別の確認が必要です。`Test-WebAutomation.ps1` で再検証できます（ローカル通信とテスト用Edgeの起動が必要）。参考：[Edge DevTools Protocol](https://learn.microsoft.com/microsoft-edge/devtools/protocol/)、[DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/)。

実装の参考：[Microsoft UI Automationのボタン実行](https://learn.microsoft.com/dotnet/api/system.windows.automation.invokepattern)、[入力欄への入力](https://learn.microsoft.com/en-us/dotnet/framework/ui-automation/add-content-to-a-text-box-using-ui-automation)。

## 実行中の停止

一覧の「実行状態」列に、実行中・完了・エラー・中断と行番号を表示します。実行中の行は薄い黄色で表示し、自動スクロールします。エラー時は該当行を薄い赤で残し、画面下部の状態欄とログにも行番号・操作名・エラー内容を表示します。部分実行でも元のシナリオの行番号を使用します。次の実行時に前回の表示をリセットします。実行状態は保存するシナリオには含まれません。

上部のボタン群にある「実行停止」を押してください。実行中のみ有効になり、実行開始前の3秒間や待機中も停止できます。Esc長押しも使用できます。停止後は実行済みの操作を取り消さず、後続の操作を中断します。外部アプリへのUI Automation呼び出しなどが応答待ちの場合、停止ボタンの処理は呼び出しから戻った後になります。

## シナリオをダブルクリックで実行する

「実行ファイル保存」を押し、保存先とファイル名を指定してください。保存時点の全行・シナリオ・実行プログラムを、1つのVBSファイルにまとめます。選択行だけの書き出しではありません。

保存したVBSをダブルクリックすると、黒いコンソールを表示せず実行画面が開き、3秒後にシナリオを自動実行します。停止ボタンも使用できます。終了後はログ確認のため画面が残ります。閉じると、一時展開した実行スクリプトを削除します。強制終了時には一時ファイルが残る場合があります。

実行用VBSの画面でも「実行ファイル保存」を使用できます。受け取った人が行を編集し、別の名前のVBSとして保存して渡せます。元のRPA Studioやモジュールファイルがなくても再保存でき、その新しいVBSからさらに編集・再保存することも可能です。「名前を付けて保存」はJSON、「実行ファイル保存」は実行用VBSを作成します。編集前の自動実行を止めたい場合は、起動後の3秒間に「実行停止」を押してください。

この機能は最新版から作成したVBSに含まれます。過去に作成したVBSには自動反映されないため、最新版RPA Studioから一度作り直してください。元のJSONがない場合は、古いVBS画面の「名前を付けて保存」でJSONを保存し、最新版RPA Studioで開いて実行ファイル保存を行えます。

元のRPA Studioのフォルダーがなくても実行できますが、Windows PowerShell 5.1・Windows Script Host・対象アプリが必要です。これはEXE形式ではありません。書き出し後にシナリオを編集した場合は、実行ファイルをもう一度保存してください。対象アプリのパスや要素情報、座標などは実行先の環境に合わせる必要があります。VBS内のシナリオ全体は暗号化されませんが、専用のID入力・パスワード入力で登録した入力情報は暗号文のまま含まれます。同じWindowsユーザーの暗号化環境で実行してください。

## ID・パスワードの暗号化保存

1. 操作を追加して「ID入力」または「パスワード入力」を選びます。
2. その行を選択し、「入力情報設定」を押して入力内容を登録します。設定画面では伏せ字で入力し、一覧には「[暗号化済み]」だけを表示します。既存の内容は再表示しません。変更する場合は新しい内容で登録し直します。
3. 入力欄を指定したい場合は、その行の「要素取得」を使います。操作の種類はID入力・パスワード入力のまま維持されます。
4. 保存ボタンまたはCtrl＋Sでシナリオを保存します。「実行ファイル保存」で書き出すVBSにも暗号文だけを含めます。

対象欄が直接入力に対応している場合は内容を置き換えます。パスワード欄など直接入力に対応していない場合は、対象にフォーカスを移して文字をキー入力します。この方式では既存の文字に追記されるので、必要なら事前に欄を空にしてください。対象要素を指定しない場合も、事前のクリック・Tabなどでフォーカスした欄へキー入力します。入力中に対象やウィンドウのフォーカスが変わった場合は中断します。クリップボードは使いません。入力先のアプリやWebサイトでの表示・保存は、その入力先の動作に従います。

暗号化はWindows DPAPIのCurrentUser方式です。通常、同じPC・同じWindowsユーザーで復号できます。他のユーザーやPCでは再登録が必要です。暗号化キーをシナリオへ埋め込んだり、固定パスワードで共用したりしません。復号して自動入力する必要があるため、一方向のハッシュ化は使いません。同じユーザー権限で動くプログラムからのアクセスや、実行中のメモリーまで防ぐ仕組みではありません。復号した文字列は入力時に一時的にメモリーへ存在します。

通常の「文字入力」「要素入力」の値は平文保存されます。既存の平文パスワードが自動で暗号化されるわけではないため、専用操作で登録し直し、以前のJSON・VBS・バックアップも必要に応じて見直してください。暗号化対象は入力内容だけで、要素名などの検索情報は平文です。

参考：[Microsoft DPAPI](https://learn.microsoft.com/dotnet/api/system.security.cryptography.protecteddata)。検証用の `Test-Credentials.ps1` は架空の入力情報を使い、暗号化・復号、保存・読込、書き出し、日本語と記号を含むID・パスワードの入力をテストします。

## 日付入力

行を選択して「日付入力設定」を押すと、操作を「日付入力」に設定できます。基準日（実行日／指定日）、前後の日数、書式を選びます。書式は直接入力もでき、画面の「入力例」で確認できます。実行日は日本時間で判定し、1回のシナリオ内では実行開始時の日付を共通で使います。保存時の日付で固定する方式ではありません。指定日を使う場合だけ、選んだ日付を保存します。

2026年10月22日の入力例：

|書式|入力結果|
|---|---|
|yyyy / yy|2026 / 26|
|M / MM|10 / 10（2月なら2 / 02）|
|d / dd|22 / 22（3日なら3 / 03）|
|yyyy/MM/dd|2026/10/22|
|yyyy-MM-dd|2026-10-22|
|yyyy.MM.dd|2026.10.22|
|yyyyMMdd|20261022|
|yyyy-MM|2026-10|
|MM/dd / M/d|10/22|
|MM.dd / M.d|10.22|
|MMdd|1022|
|yyyy年M月d日|2026年10月22日|
|M月d日|10月22日|
|yyyy/MM/dd(ddd)|2026/10/22(木)|

日数の加減算は「-1」で前日、「1」で翌日です。月末・年末・うるう日も日付として計算します。書式の月は大文字の `M` を使います。2桁表示は `MM`・`dd`、ゼロ埋めなしは `M`・`d` です。書式のカスタム入力は.NETの日付書式です。

入力先を指定しない場合は、現在フォーカスしている欄へクリップボード経由で貼り付けます。「要素取得」ならアプリの入力欄、「ウェブ要素取得」なら専用Edgeの入力欄を指定できます。日付入力の行でこれらの取得をしても操作は日付入力のままです。Excelへ入力する場合は、日付入力の行を選び「Excel操作設定」でセル入力先を設定してください。シナリオの前に「Excelブックを開く」が必要です。Excelへの日付は指定書式の文字列として保存します。

Webの `input type="date"` は通常 `yyyy-MM-dd`、`type="month"` は `yyyy-MM` を指定してください。区切り文字を自由に指定できるのは、入力先がその文字列を受け付ける場合です。年・月・日が別々の欄なら、それぞれの欄に日付入力の行を作り、`yyyy`・`MM`・`dd` などを設定します。

日付設定・入力先はJSONや実行用VBSへ保存されます。`Test-DateAutomation.ps1` で各形式、前後の日付、うるう年、設定画面のプレビュー、入力先への振り分け、保存・書き出しを検証できます。

## Excel操作

操作一覧にExcel操作を追加しています。行を選んで上部の「Excel操作設定」を押すと、操作の種類・値・シート名・セル番地を設定できます。ファイルは「参照」から選択できます。Windows版のデスクトップExcelが必要です。

|操作|指定内容|
|---|---|
|Excelブックを開く|値に既存ファイルの絶対パス（xlsx/xlsm/xlsb/xls）|
|Excelシート選択|値にシート名（例：Sheet1）|
|Excelセル入力|値に入力文字、設定画面にセル番地（例：A1）。シート名が空欄なら選択中のシート|
|Excelセル選択|セル番地（例：B3）を指定。セルの内容は変更しません|
|Excelシート印刷|対象シートをExcelで選択中のプリンターに印刷します|
|ExcelシートPDF保存|保存先フォルダーを指定。日本時間の実行日で `yyyy.MM.dd.pdf` として保存します|

月別に保存するには、PDF保存先に `C:\帳票\{年月}` と指定します。「参照」で親フォルダーを選び、「年月フォルダーを追加」を押しても設定できます。例えば11月5日の実行なら `C:\帳票\2026年11月\2026.11.05.pdf` に保存します。年月フォルダーがない場合は、既存の親フォルダーの直下に作成します。

シート名にも `{年月}` を指定できます。「Excelシート選択」の値や、セル操作・印刷・PDF保存の対象シート名に設定すると、実行日の `2026年11月` のような既存シートを参照します。シートは新規作成しません。

行を選び「メール作成設定」を押すと、宛先・件名・自由記入の本文・添付ファイルを指定できます。本文の初期値は `{noncoverpage}` です。本文はそのまま保存します。添付パスには `C:\帳票\{年月}\{日付}.pdf` のように指定でき、PDF保存の次の行に設定すると、その日のPDFを添付できます。「メール作成」は、メールプロファイルを設定したクラシック Outlookの下書きに保存します。送信はしません。添付処理に失敗した場合、途中の下書きが残ることがあります。添付ファイル自体はシナリオや実行用VBSには同梱されません。参考：[Outlookの添付ファイル操作](https://learn.microsoft.com/ja-jp/office/vba/api/outlook.attachments.add)。

セル選択・印刷・PDF保存は、対象シート名が空欄なら選択中のシートを使います。印刷・PDF保存はシートの印刷範囲設定に従います。同名のPDFがある場合は上書きせず停止します。PDF出力には [Excelの固定形式エクスポート](https://learn.microsoft.com/ja-jp/office/vba/api/excel.worksheet.exportasfixedformat) を使います。
|Excelブック保存|操作中のブックを上書き保存。値は不要|
|Excelブックを閉じる|保存済みのブックを閉じる。値は不要|

基本のシナリオは「Excelブックを開く → Excelシート選択 → Excelセル入力 → Excelブック保存 → Excelブックを閉じる」です。複数セルに入力する場合はセル入力の行を追加します。セル入力は1セル単位で、書式を文字列にして内容を置き換えます。先頭の0を残せます。数値や数式としての入力、範囲一括処理、新規ブック作成は現在のメニューには含めていません。

RPAが専用のExcelインスタンスを作成し、そこで開いたブックを操作します。既に開いている他のExcelへ接続する方式ではありません。ブックに未保存の変更がある場合、閉じる操作や別ブックへの切替を停止するため、先に保存操作を入れてください。読み取り専用のブックへの入力・上書き保存も停止します。Excel終了時は、このインスタンスに他のブックがない場合だけExcel自体を終了します。

シナリオ停止時やRPA Studio終了時には、未保存の内容を保持するためExcelを自動終了しません。必要に応じてExcel側で保存・終了してください。ファイルを開く際は外部リンクを更新せず、マクロを無効化します。パスワード保護などによりExcel側のダイアログが出た場合は、そこでの対応が必要になる場合があります。COM呼び出し中の停止ボタンは、Excelから応答が戻ってから処理されます。

テスト用ブックを使い、シナリオ実行・シート選択・日本語と先頭0のセル入力・保存後の再読込・未保存時の終了抑止・実行ファイル書き出しを確認しています。`Test-ExcelAutomation.ps1` で検証できます。参考：[Excel Workbooks.Open](https://learn.microsoft.com/en-us/office/vba/api/Excel.Workbooks.Open)。

## 制約

- 座標・キーボード操作、UI Automation、専用EdgeでのCSSセレクターによるWeb操作に対応します。Web要素は出現・操作可能になるまで待機しますが、サイトの業務処理の完了までは判定しません。必要に応じて待機時間を設定してください。
- 座標はウィンドウの位置、画面解像度、表示倍率に依存します。実行中はPCを操作せず、ロックやスリープを避けてください。
- 管理者権限のアプリ、UAC画面などには通常権限から操作できない場合があります。
- 「文字入力」でクリップボードの内容を上書きします。ID・パスワードには暗号化保存できる専用操作を使用してください。
- ウィンドウを手動で閉じるとき、未保存の変更があれば確認が出ます。「はい」で保存（既存のJSONは上書き、保存先がなければ名前を付けて保存）、「いいえ」で保存せず終了、「キャンセル」で編集に戻ります。保存先の選択を取り消した場合や保存に失敗した場合も画面は閉じません。シナリオ内の「RPA終了」は確認を出さずに終了します。
- 外部から入手したシナリオは実行前に内容を確認してください。アプリ起動や入力・クリックを含みます。
